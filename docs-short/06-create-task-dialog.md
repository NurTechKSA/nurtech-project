# Диалог создания задачи

Связан с [01-scope.md](01-scope.md), [04-board.md](04-board.md), [05-task-card.md](05-task-card.md). Макет: [wireframes/create-task/dialog.svg](wireframes/create-task/dialog.svg) (Task по умолчанию, Subtask с ошибками, Bug с шаблоном, отправка).

## 1. Назначение и вызов
Единая форма создания Task, Bug и Subtask со всеми полями карточки. Права: `task-create`.
- «+ Задача» на доске.
- «+ Подзадача» в карточке задачи (в диалоге и на странице): тот же диалог с типом Subtask и подставленным родителем.
- Быстрого создания в колонке нет.

## 2. Раскладка
Диалог шириной около 900 px.
- Сверху переключатель типа: Task / Bug / Subtask (по умолчанию Task).
- Левая колонка: «Название *» и «Описание» (markdown с панелью форматирования и «Редактор / Просмотр»).
- Правая колонка (затенённая): Родитель * (только у Subtask), Статус, Приоритет, Исполнитель, Ревьюер, Направление, К дате, Оценка, Теги.
- Внизу «Отмена» и «Создать» одной ширины.
Связи, ссылки, комментарии и время задаются уже в карточке.

## 3. Поведение
**Значения по умолчанию.** Тип Task. Статус: с доски — первая колонка доски; из карточки — первый статус проекта (Backlog в шаблоне `dev`). Приоритет Medium. Остальное пусто. Статусы с `requiresReason` (Blocked, Cancelled) в списке не предлагаются. С доски «Разработка» задача попадает в To do и минует планирование — это осознанно.

**Переключение типа.**
- Bug: если описание пустое, подставляется шаблон (Шаги воспроизведения / Ожидаемый результат / Фактический результат). При возврате на Task описание остаётся как есть.
- Subtask: появляется обязательное «Родитель» — поиск по ключу или названию среди Task и Bug проекта (`GET /projects/:projectId/tasks/search?types=task,bug`). Если диалог открыт из карточки, родитель уже выбран и его можно заменить.
- Task и Bug: «Родитель» скрыт, выбранное значение сбрасывается.

**Валидация.** «Создать» всегда активна; при пустых обязательных полях ошибка под полем («Введите название», «Не больше 100 символов», «Выберите родительскую задачу»), фокус на первое такое поле.

**Поля** — те же компоненты, что в панели полей карточки: Статус и Приоритет (списки), Исполнитель и Ревьюер (поиск по участникам, «Я», «Не назначен», «Назначить на меня»), Направление (если у проекта есть), К дате, Оценка (`2h 30m`), Теги («+ Тег», создание нового по `tag-create`).

**Закрытие.** Если что-то введено или изменено, «Отмена», ✕ и Esc спрашивают «Закрыть без сохранения?» («Остаться» / «Закрыть без сохранения»); пустая форма закрывается сразу. Клик вне диалога не закрывает его.

**Отправка.** Поверх диалога индикатор, текст кнопки не меняется. При ошибке диалог остаётся открытым с данными; 422 — тексты под полями, остальное — общее сообщение.

**После создания.** Диалог закрывается, открывается карточка новой задачи: с доски — диалогом (`?task=`), со страницы карточки — страницей новой задачи. Доска перезапрашивается.

## 4. Права
`task-create` на весь диалог; `tag-create` для нового тега. Viewer не видит «+ Задача» и «+ Подзадача».

## 5. API
- Создание — `POST /projects/:projectId/tasks`, ответ — созданная задача с ключом.
- Родитель — `GET /projects/:projectId/tasks/search?types=task,bug`.
- Значения полей — `GET /projects/:projectId/statuses`, `/members`, `/subsystems`, `/tags`.
ТЗ — [backend/02](backend/02-tasks.md).

## 6. Сценарии
- **C1** Создать Task → открывается карточка.
- **C2** Создать Bug с шаблоном описания.
- **C3** Создать Subtask из карточки.
- **C4** Ошибки валидации.
- **C5** Отмена с подтверждением.
- **C6** Ошибка сервера.

## Приёмка
Формат и сид — как в [04](04-board.md), раздел «Приёмка».

**C1 Task**
- C1.1 Дано: `clara_member`, «Разработка». Действие: «+ Задача», название, «Создать». Ожидаю: открылся диалог карточки с новым ключом; Task, Medium, To do; на доске карточка в конце To do.
- C1.2 Дано: «+ Подзадача» из страницы карточки. Действие: заполнить все поля (исполнитель «Я», ревьюер, направление, срок, оценка `1h`, теги, описание), «Создать». Ожидаю: открылась страница новой подзадачи со всеми значениями; статус — Backlog.
- C1.3 Ожидаю: в списке статусов нет Blocked и Cancelled.
- C1.4 Дано: `eva_viewer`. Ожидаю: «+ Задача» и «+ Подзадача» нет.

**C2 Bug**
- C2.1 Дано: пустое описание. Действие: тип Bug. Ожидаю: подставлен шаблон.
- C2.2 Дано: описание введено. Действие: тип Bug. Ожидаю: текст не заменён.
- C2.3 Дано: шаблон подставлен. Действие: вернуть Task. Ожидаю: описание осталось.

**C3 Subtask**
- C3.1 Дано: карточка Task. Действие: «+ Подзадача». Ожидаю: тип Subtask, «Родитель» заполнен и может быть заменён.
- C3.2 Действие: в обычном диалоге выбрать Subtask. Ожидаю: появилось «Родитель *»; поиск находит только Task и Bug проекта.
- C3.3 Действие: Subtask → Task. Ожидаю: поле скрыто, значение сброшено.

**C4 Валидация**
- C4.1 Действие: «Создать» на пустой форме. Ожидаю: кнопка не была отключена; «Введите название», фокус на названии.
- C4.2 Дано: 101 символ. Ожидаю: «Не больше 100 символов».
- C4.3 Дано: Subtask без родителя. Ожидаю: «Выберите родительскую задачу», фокус на «Родитель».

**C5 Отмена**
- C5.1 Дано: пустая форма. Действие: «Отмена», ✕, Esc. Ожидаю: закрывается сразу.
- C5.2 Дано: введено название. Действие: «Отмена», ✕, Esc. Ожидаю: «Закрыть без сохранения?»; «Остаться» сохраняет форму, «Закрыть без сохранения» закрывает.
- C5.3 Действие: клик вне диалога. Ожидаю: не закрывается.

**C6 Ошибка сервера**
- C6.1 Дано: остановлен бэкенд. Действие: «Создать». Ожидаю: индикатор поверх диалога, текст кнопки прежний; затем общее сообщение, данные на месте; после восстановления повторное «Создать» срабатывает.
