# Task-manager MVP: границы и решения

Укороченная версия проекта для разработки с учениками. Полная версия (целевое состояние продукта) лежит в `docs/` и не меняется: после MVP проект дорабатывается по ней, в том числе с ИИ-агентами.

## Контекст
Учебный проект с «коммерческим» процессом: 12–14 учеников (в плане 13) по ≈ 7 ч в неделю, Angular 21 + Taiga UI 5 + ngrx-signals, без тестов. Ревью и мердж — ментор. Бэкенд пишет отдельный разработчик. Полная версия (≈ 490 ч учеников, 80 ручек) за курс не помещается, поэтому MVP — это **доска задач и карточка задачи**: минимальный продукт, которым уже можно пользоваться.

**Как начинается работа.** Каркас ментора готов: вход по паролю, сессия, гарды, перехватчики ошибок API, layout с верхней панелью, переключатель проектов, меню пользователя, права в проекте, экраны «Не найдено» и «Вас ещё не добавили в проекты» — пример архитектуры и чистого кода (README репозитория). Бэкенд готов целиком и работает на стенде; пользователи и проекты заведены сидом. Сначала ученики делают небольшие задачи для знакомства с проектом, затем — доску и карточку ([02](02-plan.md)).

**Тестовые пользователи.** На время разработки все работают под общими пользователями сида (`anna_owner`, `boris_admin`, `clara_member`, `denis_member`, `eva_viewer`, `hanna_free`). На странице входа они перечислены карточками, в меню аватара есть «Войти как». Это временный код в `src/temp`, в продукт он не входит.

## Что входит
| Область | Что есть в MVP |
|---|---|
| Доступ | Вход по логину и паролю (каркас); принятие ссылки-приглашения (логин и пароль); выход; профиль (имя, логин только для чтения, смена пароля) |
| Проекты | Переключатель проектов; роли owner / admin / member / viewer с ключами разрешений (`*appRestrictByPermission`); пользователей, проекты и участников заводит разработчик бэкенда |
| Доски | Доски «Разработка» и «Планирование» из шаблона (и доски-фильтры, которые добавит бэкендер); переключатель досок; drag&drop с ручным порядком; диалог причины (Blocked, Cancelled); фильтры (исполнитель, ревьюер, приоритет, тип, направление, теги) и поиск; колонка Done за 14 дней; автообновление раз в 30 секунд |
| Создание задачи | Диалог для Task / Bug / Subtask со всеми полями карточки; шаблон описания для Bug |
| Карточка задачи | Один компонент в двух оболочках: **диалог** поверх доски (`?task=KEY`) и **отдельная страница** `/project/PROJ/tasks/PROJ-123`. Поля с автосохранением, теги (создание на лету), направление, описание (markdown), подзадачи, связи «Блокирует / Заблокирована», ссылки, вкладки «Комментарии» (с «Показать ещё»), «Время», «История» |
| Справочники | Статусы, доски и направления создаёт шаблон проекта; теги — на лету из задачи |

## Что не входит (после MVP, по `docs/`)
- Telegram: вход, привязка, бот, уведомления.
- Уведомления в приложении (колокольчик), подписки на задачу (☆), уведомления об @упоминаниях. «Ответить» в комментарии просто вставляет `@username` в текст.
- Администрирование: пользователи, приглашения, проекты, смена владельца.
- Страница «Участники»: добавление, смена роли, удаление участников.
- Настройки проекта: общие, направления, теги, редакторы статусов и досок.
- Список «Все задачи» и раздел «Списки» в переключателе видов; ссылка «все закрытые →» в колонке Done.
- Архивация и восстановление задач: ненужную задачу закрывают статусом Cancelled.
- Принудительная смена пароля при первом входе, деактивация пользователей.
- Всё, что не входит в полную версию: эпики, спринты, кастомные поля и роли, вложения, SSE и т. д. (`docs/01-scope.md`, «Не входит»).

## Что изменено против полной версии
| Было в `docs/` | Стало в MVP | Почему |
|---|---|---|
| Карточка — «боковая панель», `/project/PROJ/tasks/PROJ-123` — входная ссылка с редиректом | Карточка — диалог поверх доски и полноценная отдельная страница; один компонент содержимого в двух оболочках | решение ментора: практика с одним компонентом в двух контекстах |
| Фронт обрабатывает отдельные коды 409 (`stale_position` тихо, гонка тега через `details.tag`, `task_archived` и др.) | Любой 409: откат, `message` бэкенда, перезапрос данных | меньше веток на фронте, бэкенд пишет понятный `message` |
| Подзадачи — отдельный запрос | Подзадачи приходят в ответе карточки | один запрос вместо двух |
| Переключатель видов: «Доски» и «Списки» | Переключатель досок | списка нет |
| ⚙ меню проекта, 🔔 уведомления в верхней панели | Нет | страниц «Участники», «Настройки» и уведомлений нет |
| Архивация задачи, баннер архива, «Восстановить» | Нет; закрыть ненужную задачу — статус Cancelled | без списка архивную задачу негде найти |
| Экраны «Нет доступа» (403) и «Доска не найдена» с «Открыть первую доску» | Один экран `/not-found` «Не найдено или недостаточно прав» с «На главную» | одно место для всех ненайденных ресурсов |

Контракт MVP — подмножество полного контракта 0.7.0 с теми же путями и именами полей; отличия — [backend/openapi/CHANGELOG.md](backend/openapi/CHANGELOG.md).

## Роли
- **owner, admin** — всё, что есть в MVP, плюс удаление чужих комментариев и правка чужих списаний времени. В MVP по правам не различаются.
- **member** — создание и правка задач, перенос, связи и ссылки, комментарии, списание времени; своё правит и удаляет.
- **viewer** — просмотр, комментарии (свои правит и удаляет); без перетаскивания, создания и правки.
Матрица ключей — [08](08-data-model-and-permissions.md), раздел 4.

## Адреса
| Адрес | Что |
|---|---|
| `/login` | вход (каркас) |
| `/invite/:token` | принятие приглашения |
| `/profile` | профиль |
| `/project/PROJ/board/:id` | доска; `?task=PROJ-123` — открытый диалог карточки; фильтры и поиск — в query |
| `/project/PROJ/tasks/PROJ-123` | карточка задачи отдельной страницей |
| `/project/PROJ` | редирект на последнюю использованную доску проекта (если её нет — на первую) |
| `/` | редирект в последний открытый проект (если его нет — в первый); без проектов — «Вас ещё не добавили в проекты» |
| `/not-found` | «Не найдено или недостаточно прав»: несуществующий проект, доска, задача или неизвестный адрес |
| `/project/PROJ/data` | временная страница с ответами API проекта (`src/temp`); пока нет доски, главная ведёт на неё |

## Общие решения
- Автосохранение полей карточки; описание и комментарии — кнопкой «Сохранить» / «Отправить».
- Недоступные действия скрываются; viewer не перетаскивает карточки.
- Фильтры и открытая задача — в query-параметрах; между сессиями запоминаются только последний проект и последняя доска проекта (на устройстве).
- Для каждого экрана с данными — загрузка, пусто, «ничего не найдено», ошибка ([03-ui-rules.md](03-ui-rules.md)).
- Интерфейс только русский; доска только для десктопа.
